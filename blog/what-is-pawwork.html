What Is PawWork? A Free, Open-Source Desktop AI Agent — and How to Run It

Most AI assistants live in a browser tab and can only talk about your work. PawWork puts the agent on your desktop, where your actual files are.

There is a quiet but important shift happening in agentic AI. The first wave of assistants lived in a chat window: you pasted content in, you copied answers out, and every real artifact — the spreadsheet, the invoice folder, the test report — stayed on your machine, untouched. The second wave moved into the IDE and served developers well, but left everyone else behind. PawWork belongs to a third category: a desktop agent that opens your real folders, reads and writes real Office files, and does the work where the work actually lives.

It is free, open-source (Apache-2.0), and available for macOS and Windows. It positions itself openly as an alternative to closed desktop agents like OpenAI's Codex App and Claude's desktop work mode — with the difference that you can read its source, point it at any model provider you like, and run it without a subscription.

What PawWork Actually Is

Under the hood, PawWork is a desktop shell built on a fork of OpenCode — a mature open-source agent engine. The project keeps that engine and rebuilds the experience around it: instead of a terminal and a developer-shaped workflow, you get an Electron desktop app with task cards, plain-language input, and a file-approval step before anything is written to disk. The stack is TypeScript with Electron and SolidJS on the front, Bun for tooling, and some Rust in the mix.

The important design decision is scope. PawWork is not a coding agent that happens to open files; it is a work agent. Its native material is the ordinary contents of a knowledge worker's Documents folder: PDFs, Word documents, Excel workbooks, PowerPoint decks, CSVs, Markdown, images, and code. It reads them locally, edits them locally, and saves them back locally.

The one-line version: PawWork is an open-source desktop agent that brings the model to your files, instead of asking you to bring your files to the model.

The Features That Matter

1

Bring Your Own Key — 75+ Providers

OpenAI, Anthropic, Google Gemini, DeepSeek, Kimi, GLM, and any OpenAI-compatible endpoint. Local models work too through Ollama or LM Studio, which means you can run entire workflows without a single token leaving your machine. There is also ChatGPT OAuth sign-in for Plus/Pro users, and a free built-in plan with a web-search quota so you can start with no key at all.

2

Real Office File Support

Reading a .docx is common; writing a correct one is not. PawWork handles both directions for Word, Excel, and PowerPoint, plus PDF operations like extraction and merging. This is the feature that makes it usable by people who are not engineers — the deliverable comes back as a file they can open, not as text in a chat bubble.

3

Web Search and Browser Adapters

Research tasks are first-class: the agent can search the web, collect sources, and turn them into a memo or a spreadsheet. Browser-based adapters extend this to interacting with supported web services rather than only reading static pages.

4

Task Cards Instead of a Blank Prompt

A blank chat box is the worst onboarding in software. PawWork opens with concrete task cards — extract invoice data, merge these PDFs, summarise this folder, review this project — which is a small UX choice with a large effect on whether non-technical colleagues ever get past the first session.

Note the fifth row carefully, because it cuts both ways. Full workspace access is exactly why PawWork can be useful on day one — and exactly why you should point it at a scoped folder rather than your entire home directory until you trust it.

Getting It Running

There are two paths. Most people want the installer.

Install the release build. Grab the latest release from the project's GitHub releases page: a .dmg for macOS (Apple Silicon and Intel; signed and notarised) or an .exe for Windows x64. The Windows installer is currently unsigned, so SmartScreen will warn you — verify you downloaded it from the official repository before clicking through, and if you are on a managed corporate laptop, ask IT first rather than dismissing the warning.

Build from source. If you would rather read the code before you run it — a reasonable instinct for anything with full disk access — you need Bun v1.2 or newer:

git clone https://github.com/Astro-Han/pawwork.git
cd pawwork
bun install
bun run dev:desktop

A caution worth stating plainly: PawWork appears on GitHub under several accounts, including forks and mirrors. Before you install or clone, check the star count, commit history, and release signatures, and prefer the repository the project's own documentation points to. This applies to every open-source desktop agent, not just this one.

First-run setup, in order: connect a model — either the built-in free plan, a provider API key, ChatGPT OAuth, or a local Ollama/LM Studio endpoint; then choose a workspace folder, and make it a narrow one for your first few sessions; then run one small, reversible task, such as summarising a folder of PDFs, and read the proposed file actions before approving them. Only after that should you give it anything you would be upset to lose.

Treat the approval step as the product's most important feature, not a speed bump. An agent with write access to your Documents folder deserves the same review discipline you would give a pull request.

Where It Fits in a QA Workflow

A desktop agent is not a test automation framework, and it will not replace Playwright, WebdriverIO, or Appium. What it replaces is the unglamorous half of QA work that surrounds the automation — the part that quietly eats a day a week.

Concretely: turning a folder of requirement documents into a first-pass test scenario list in Excel; consolidating twelve HTML reports from separate runs into one summary; converting a raw defect export into the template your client expects; reading a long specification PDF and pulling out every acceptance criterion; drafting release notes from a changelog. Each of these is a file-in, file-out task with a known shape — which is exactly what a desktop agent is good at, and exactly what a browser chat window is bad at, because the files never leave your machine to begin with.

For anyone working under client confidentiality or handling regulated data, the BYOK-plus-local-models combination is the genuinely interesting part. Running a local model against a local workspace means the documents never touch a third-party API — a property that is hard to get any other way, and worth the lower model quality in the cases where it matters.

The Honest Limitations

PawWork is a young project, and young projects break. The Windows installer being unsigned is a real friction point in corporate environments. Output quality is entirely a function of the model you connect — a free tier will not match a frontier model on a complex document task, and no amount of good UX changes that. Full workspace access is powerful and risky in equal measure. And as a general-purpose work agent, it will lose to specialised tools on their home turf: a dedicated coding agent will write better code, a dedicated RPA tool will automate better.

None of that makes it a bad bet. It makes it a tool to adopt deliberately: scoped folder, reviewed actions, a model you chose on purpose. If the promise of agentic AI is that software finally does the boring parts of knowledge work, PawWork is one of the more credible open-source attempts to deliver it — and because it is open source, you can see exactly how it is trying.
